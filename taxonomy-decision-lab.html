Can a clearer display help clinicians read delirium risk?

A risk tool helps only if the people using it read its output correctly. The same output can be read well or poorly depending on how it is displayed, where it is used, how reliable it is, and how much attention it gets. This page tests that with clinicians first, then lets anyone explore why.

For the research team: how to run this test
  1. Send each participant one link. The group 1 link shows the score-only display on cases 1, 3, and 5, and the group 2 link shows it on cases 2, 4, and 6. Alternate the links between participants so every case is seen both ways. A link without a group picks one at random.
  2. Ask participants to take the test before exploring the rest of this page. The sections below explain the very issues the test measures.
  3. Collect the CSV files. Each has one row per case: participant code, role, years in practice, group, case, display version, estimate, reference risk, points off, action, confidence from 1 to 5, seconds spent on the case, comment, and finish time. Nothing is sent from the page.
  4. Compare the two versions case by case across participants: points off, confidence, the actions chosen, and time.

Before collecting answers, pilot the test with two or three clinicians and check whether your institution’s review board needs to approve the study. The cases and reference risks are illustrative. The full display states each scenario’s recalibrated estimate, except in case 4, where it warns that the model likely underestimates, so differences in accuracy mainly show whether clinicians can use what a display communicates.

    3 · Model robustness

    Sample size, performance, and what a display leaves out

    A single performance number hides how sure we are about it and whether it still holds after deployment. Both demonstrations start from what Jauk et al. reported: an AUROC of 0.854 on the test data and 0.855 during seven months of prospective use, while calibration deteriorated.

      Report performance with its uncertainty and the size of the evaluation behind it, and keep checking calibration after deployment. A display that encodes only rank cannot show drift, so reliability has to be communicated, not only measured.

      4 · What if

      What if the output does not get full attention?

      Alerts compete with interruptions, time pressure, and other alarms. Drag attention toward “rushed” and switch off what the display communicates. The less attention there is, the more the display has to carry on its own, and the more support the decision needs.
